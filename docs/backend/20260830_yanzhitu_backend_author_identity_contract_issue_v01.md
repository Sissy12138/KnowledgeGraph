# 研知图后端问题：作者身份必须使用稳定 ID

## 结论

作者合作关系不能通过作者姓名匹配或反查作者 ID。后端论文接口必须返回稳定、唯一的作者标识；图谱服务应使用作者 ID 派生共同作者关系，姓名仅用于界面展示。

## 问题背景

当前前端 Mock 同时包含论文作者姓名和作者节点。若根据 `authorNames` 建立“姓名 → 作者 ID”映射，会隐含“姓名全局唯一”的错误假设。

真实数据中可能出现：

- 两位作者同名但属于不同机构；
- 同一作者使用中文名、英文名、缩写或曾用名；
- 姓名拼写、顺序、空格和大小写发生变化；
- ORCID 缺失或尚未确认。

因此，姓名规范化无法替代实体身份解析。使用姓名派生合作边可能造成错连、漏连或错误的共同论文权重。

## 后端接口要求

### 1. 论文必须返回稳定作者 ID

推荐论文摘要结构：

```json
{
  "id": "paper-001",
  "title": "Reversal learning reveals flexible cognitive control",
  "authors": [
    {
      "id": "author-001",
      "displayName": "王芳",
      "orcid": "0000-0003-1415-9265",
      "affiliations": ["研知大学计算神经科学实验室"]
    },
    {
      "id": "author-002",
      "displayName": "李明",
      "orcid": null,
      "affiliations": ["研知大学认知科学中心"]
    }
  ]
}
```

如果论文列表接口需要保持轻量，也至少应返回：

```json
{
  "authorIds": ["author-001", "author-002"],
  "authorNames": ["王芳", "李明"]
}
```

`authorIds` 与 `authorNames` 必须按相同顺序一一对应；更推荐使用包含 `id` 和 `displayName` 的对象数组，避免平行数组错位。

### 2. ID 的稳定性约束

- `author.id` 在同一数据环境内唯一且长期稳定。
- 修改姓名、单位或 ORCID 不得改变作者 ID。
- 两位同名作者必须拥有不同 ID。
- 同一作者的别名、缩写和不同语言写法应解析到同一 ID。
- ORCID 可用于身份解析，但不能作为唯一必填主键，因为部分作者没有 ORCID。

### 3. 共著关系派生规则

对于一篇已审核通过的论文：

1. 读取去重后的稳定作者 ID 集合。
2. 对作者 ID 做两两无序组合。
3. 将论文 ID 加入对应作者对的 `sourcePaperIds`。
4. 最终令 `weight = sourcePaperIds` 去重后的数量。

建议返回结构：

```json
{
  "id": "coauthor-author-001-author-002",
  "sourceId": "author-001",
  "targetId": "author-002",
  "relationType": "coAuthor",
  "directed": false,
  "sourcePaperIds": ["paper-001", "paper-003"],
  "weight": 2
}
```

边 ID 应由排序后的两个作者 ID 生成，不能包含姓名。

## 后端数据校验规则

- 论文中的每个 `authorId` 必须引用存在的作者实体。
- 同一论文内 `authorId` 不得重复。
- 每条 `coAuthor` 边的两个端点必须是不同作者 ID。
- `sourcePaperIds` 中每篇论文必须同时包含该边的两个作者 ID。
- `weight` 必须等于去重后的 `sourcePaperIds.length`。
- 独立作者允许没有合作边。
- 待审核作者合并建议不得进入正式图谱；只使用审核通过的作者实体和论文。

## 必须覆盖的验收场景

### 同名作者

存在两个不同作者：

```text
author-101：王芳，机构 A
author-202：王芳，机构 B
```

当两人分别参与不同论文时：

- 不得被合并为同一作者；
- 合作边必须连接各自真实 ID；
- 其中一人的论文不得计入另一人的合作权重。

### 同一作者多个名字

`王芳`、`Fang Wang` 和 `F. Wang` 若已由实体解析确认属于同一作者，必须返回同一个作者 ID。

### 缺失 ORCID

作者缺少 ORCID 时仍必须有内部稳定 ID，并能正确参与论文和合作关系。

### 三位及以上作者

一篇包含三个不同作者 ID 的论文应产生三条作者对关系；包含四位作者时应产生六条，遵循组合数：

```text
边数 = n(n - 1) / 2
```

## 前端依赖与迁移影响

后端契约提供稳定作者 ID 后，前端将：

- 使用作者 ID 构建或展示合作边；
- 使用 `displayName` 展示姓名；
- 不再维护“姓名 → 作者 ID”的反向映射；
- 在同名作者界面中结合单位或 ORCID 辅助区分，但不据此重新判断身份。

在后端完成该契约前，当前前端作者合作数据只能视为界面 Mock，不能作为真实作者身份或合作统计结果。

## 后端完成标准

- 论文列表和论文详情均返回稳定作者 ID。
- 作者详情接口使用相同作者 ID。
- 图谱接口的作者节点、论文作者引用和合作边共享同一套 ID。
- 同名、别名、缺失 ORCID、独立作者及多作者论文测试全部通过。
- 数据校验能够拒绝悬空作者引用、重复作者引用和错误合作权重。
