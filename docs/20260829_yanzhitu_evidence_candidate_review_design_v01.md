# Evidence 候选审核设计

## 目标

将“新增概念/新增方法”的二元审核升级为实体消歧审核：一段 Evidence 对应一组候选实体，审核者选择 1～3 个候选，系统据此连接已有节点或创建新节点。

## 审核颗粒度

- 一张审核卡代表一段 Evidence，而不是一个候选名称。
- `addConcept` 只包含概念候选，`addMethod` 只包含方法候选。
- 候选分为 `existing`（连接已有节点）和 `new`（创建新节点）。
- 所有候选均有独立置信度；最高置信度不低于 0.70 时默认选中。
- 人工最多选择 3 个候选；拒绝与候选选择互斥。
- 同一 Evidence 可连接多个实体，并分别保存选择时的候选置信度。

## 紧凑卡片

- 标题行只显示“原文识别结果：……”。红色圆形 `×` 和绿色圆形 `√` 位于卡片右下角，尺寸约为原版的三分之二；鼠标悬停或键盘聚焦卡片时显示，触屏设备保持可见。
- 候选用小矩形按钮横向排列，空间不足时自动换行，文字格式为“名称 86%”。
- 已有候选与新建候选在未选中时使用不同背景色；所有选中项统一变为浅红背景和红色边框。
- Evidence 位于候选下方，默认限制显示行数，可展开查看全文。
- 点击 `√` 直接确认当前 1～3 个选择；无选择、名称冲突或处理中时不可确认。
- 点击 `×` 打开拒绝弹窗，原因可选填，二次确认后提交。

## 新节点名称与去重

- 选中新建候选时允许编辑规范名称，同时保留模型提取的原始名称。
- 当前 Mock 阶段先实现忽略大小写与首尾空格的精确重名检测。
- 若编辑后的名称命中卡片内已有候选，自动改选已有节点，并提示避免重复创建。
- 语义近似匹配留给后端实体检索接口，不在本轮前端 Mock 中伪造算法结果。

## 批量审核

- 批量采纳时，概念/方法卡只提交最高候选不低于 0.70 的默认选择。
- 仅在论文标题保留批量操作：浅红色小框中的红色 `×` 表示批量拒绝，浅绿色小框中的绿色 `√` 表示批量采纳；悬停显示完整提示。概念、方法、发现、关系模块内部不再重复显示批量按钮。
- 低置信度、无候选、名称冲突或未完成编辑的卡片跳过。
- 发现与关系仍沿用当前单建议采纳逻辑。
- 批量确认弹窗显示实际提交数量和跳过数量。
- 批量拒绝仍覆盖范围内全部待审核项。

## 状态与兼容范围

- 已采纳页面展示最终选中的 1～3 个候选及“连接已有/创建新节点”结果。
- 拒绝页面展示拒绝原因；未填写时显示“未填写拒绝原因”。
- 保留现有论文纵向分组、四类模块、三状态标签和 409 冲突刷新。
- 本轮只升级 `addConcept` 与 `addMethod`；`addFinding`、`addRelation` 保持原交互。
