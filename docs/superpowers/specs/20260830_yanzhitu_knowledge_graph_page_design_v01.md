# 研知图知识图谱展示页面设计 v01

## 1. 文档信息

- 日期：2026-08-30
- 适用项目：`20260823_yanzhitu_frontend_foundation_v01`
- 页面路由：`/graph`
- 当前阶段：设计已在对话中确认，等待用户审阅本文后进入实施计划
- 数据边界：首版只使用 Mock；真实接口和期刊、JIF、作者相关字段仍等待 A 确认

## 2. 目标

实现知识图谱主页面，让用户能够按不同研究对象浏览正式图谱、搜索节点、查看节点与关系详情，并从概念或作者继续进入相关论文。

首版优先验证信息结构和核心交互，不承担图谱编辑、审核或全量大图分析。

## 3. 页面总体结构

采用“分类网络 + 中央画布 + 右侧详情”布局：

```text
知识图谱

[概念网络] [方法网络] [作者合作] [文献关系]     [搜索当前网络]

┌────────────────────────────────┬──────────────────┐
│                                │ 节点或关系详情     │
│          ECharts 图谱画布       │                  │
│                                │ 定义、元数据       │
│       ○────○                   │ 相关关系           │
│        \                       │ 关联论文           │
│         ○                      │ Evidence          │
│                                │                  │
└────────────────────────────────┴──────────────────┘
```

- 页面沿用现有应用头部和左侧主导航。
- “知识图谱”导航项改为可访问 `/graph` 的链接。
- 桌面端详情面板固定在画布右侧。
- 小屏幕将详情面板显示为画布下方的详情区，避免遮挡图谱。
- 首次进入默认打开“概念网络”，并选中关联论文数最多的概念。

## 4. 四类网络

### 4.1 概念网络

画布只显示概念节点，支持正式关系：

- `broaderThan`：上位概念指向下位概念。
- `relatedTo`：概念之间的对称相关关系。

点击概念后，详情面板显示：

- 名称、定义和别名；
- 上位、下位及相关概念；
- 关联论文及作者、年份、期刊、年度 JIF；
- 论文排序入口：JIF 降序或年份降序；
- 点击论文进入现有论文详情页。

概念网络不直接把论文节点混入画布，避免节点数量快速膨胀。相关论文只在详情面板展示。

### 4.2 方法网络

画布显示论文和方法两种节点，以 `paper → method` 的 `uses` 关系连接。

点击方法后显示方法类型、描述及使用该方法的论文；点击论文后显示论文元数据及其方法列表。

首版不生成尚未进入契约的“方法共同使用”派生关系。

### 4.3 作者合作网络

画布只显示作者节点和派生 `coAuthor` 边：

- 节点大小对应作者在当前数据集中的论文数量。
- 边宽对应两位作者的共同论文数量。
- 合作边由共同论文生成，不作为独立永久关系保存。

点击作者后显示姓名、ORCID、单位、全部论文和主要合作者。点击合作边后显示两位作者、共同论文数和共同论文列表。

作者身份不能只根据姓名合并。Mock 使用稳定作者 ID；真实数据优先使用 ORCID，没有 ORCID 时等待 A 的消歧策略。

### 4.4 文献关系网络

画布只显示论文节点和正式 `cites` 关系。

点击论文后显示标题、作者、年份、期刊、年度 JIF，以及引用和被引用论文；同时列出该论文关联的概念、方法和发现摘要。

首版不增加尚未进入现行契约的 `extends` 等论文关系。

## 5. 视觉编码

不同节点类型使用稳定颜色：

| 节点类型 | 建议颜色 | 大小含义 |
|---|---|---|
| Concept | 青绿色 | 关联论文数 |
| Method | 琥珀色 | 使用论文数 |
| Paper | 靛紫色 | 当前网络中的连接数 |
| Author | 蓝色 | 作者论文数 |

- 选中节点增加明显外圈，并保持原类型颜色。
- 搜索命中的节点提高不透明度和边框，其他节点降低不透明度但不删除。
- 有方向关系显示箭头；对称关系不显示箭头。
- 作者合作边根据共同论文数改变线宽。
- 顶部或画布内提供当前网络对应的简明图例。
- 不使用颜色作为唯一的信息编码；节点标签、关系名称和选中外圈同时表达含义。

## 6. 交互

### 6.1 画布

- 滚轮缩放。
- 拖动画布平移。
- 节点可临时拖动，但位置不写入 Mock 或后端。
- 单击节点更新右侧节点详情。
- 单击关系边更新右侧关系详情。
- 单击画布空白处取消选择并显示引导信息。
- “适应画布”将当前网络重新居中并完整显示。
- “重置”清除搜索和选择，并恢复当前网络初始视图。

### 6.2 搜索

- 搜索只作用于当前网络。
- 输入时显示匹配结果列表。
- 选择结果后自动居中、选中并高亮目标节点。
- 搜索不删除不匹配节点，以免破坏关系上下文。
- 无匹配结果时显示明确提示。

### 6.3 标签切换

- 四个网络标签互不共享选中对象。
- 每个标签可保留本次页面会话中的最后选中对象；刷新页面后恢复默认对象。
- 切换标签时加载相应 Mock，并让画布适应视口。

## 7. 技术方案

使用 ECharts 的 `graph` 系列和 SVG 渲染器。

选择理由：

- 旧静态原型已经用 ECharts 验证过类似布局和交互。
- 原生支持力导向图、缩放、平移、节点拖动、边宽和提示框。
- 相比手写 SVG，首版实现和维护成本更低。
- 相比 Cytoscape.js，当前功能不需要复杂图分析能力。

React 组件通过 `ref` 创建和销毁 ECharts 实例，不额外引入 React 包装层。组件卸载时必须调用 `dispose()`，窗口或容器尺寸变化时调用 `resize()`。

## 8. 代码模块

```text
frontend/src/features/graph/
├── GraphPage.tsx
├── GraphPage.css
├── GraphToolbar.tsx
├── GraphCanvas.tsx
├── NodeInspector.tsx
├── EdgeInspector.tsx
├── graph.types.ts
├── graph.mock.ts
├── graph.service.ts
├── graph-transform.ts
└── *.test.ts(x)
```

职责：

- `GraphPage`：管理当前网络、请求状态、搜索、选中节点或边。
- `GraphToolbar`：网络标签、搜索、适应画布和重置操作。
- `GraphCanvas`：只负责绘图和把点击事件回传给页面。
- `NodeInspector`：按节点类型渲染详情。
- `EdgeInspector`：渲染普通关系或作者合作关系详情。
- `graph.types`：定义前端消费的图谱与详情结构。
- `graph.mock`：提供首版四类网络假数据。
- `graph.service`：封装数据获取；首版返回 Mock，后续替换为 API。
- `graph-transform`：把前端图谱数据转换成 ECharts 配置。

组件不直接导入具体 Mock 常量，统一通过 `graph.service` 获取数据，以便未来替换后端实现。

## 9. 前端数据结构

```typescript
type GraphView = 'concept' | 'method' | 'author' | 'paper'

type GraphNodeType =
  | 'paper'
  | 'author'
  | 'concept'
  | 'method'
  | 'finding'

type GraphNode = {
  id: string
  nodeType: GraphNodeType
  label: string
  description: string | null
  sourcePaperIds: string[]
  metrics: {
    paperCount?: number
    connectionCount?: number
  }
}

type GraphEdge = {
  id: string
  sourceId: string
  targetId: string
  relationType: string
  label: string
  directed: boolean
  weight: number | null
  evidenceIds: string[]
  sourcePaperIds: string[]
}

type GraphDataset = {
  view: GraphView
  nodes: GraphNode[]
  edges: GraphEdge[]
  evidence: Evidence[]
}
```

节点详情使用独立的联合类型，避免把作者、概念和论文的所有字段塞进同一个宽泛对象。期刊和 JIF 只存在于论文详情结构中，不成为图谱节点。

## 10. Mock 范围

- 概念网络：6–8 个概念，包含 `broaderThan` 和 `relatedTo`。
- 方法网络：4–5 个方法、4–5 篇论文及 `uses`。
- 作者合作：6–8 位作者，覆盖独立作者、普通合作和多篇合作。
- 文献关系：5–6 篇论文及 `cites`。
- 每类网络至少有一个可验证缺失字段处理的对象。
- 期刊、JIF、ORCID 等未获 A 确认的数据必须在 Mock 注释中标记为示例。
- 所有 ID 在不同 Mock 响应间保持一致。

## 11. 页面状态和错误处理

页面状态：

```typescript
type GraphRequestState = 'loading' | 'success' | 'empty' | 'error'
```

- `loading`：显示画布骨架和不可操作的详情占位。
- `success`：显示图谱和节点或关系详情。
- `empty`：显示“当前网络暂无节点”，保留网络切换入口。
- `error`：显示错误说明和“重新加载”按钮，其他网络仍可切换。
- 当前选中的节点或边在新数据中不存在时，自动清除选择。
- ECharts 初始化失败时显示可读错误，不保留空白画布。

## 12. 可访问性与响应式

- 网络标签使用可识别的标签页语义。
- 搜索框具有明确标签。
- 工具按钮提供文字或 `aria-label`。
- 详情变化使用可聚焦标题，键盘用户可以进入详情区阅读。
- 画布本身提供文字摘要，说明节点数、关系数和当前选中对象。
- 小屏幕详情区移动到画布下方；不使用覆盖整个画布的弹层。

ECharts 画布的复杂节点导航首版仍以鼠标为主；完整键盘图遍历不列入 v01，但搜索结果可通过键盘选择并定位节点。

## 14. 首版完成标准

1. `/graph` 可从主导航进入。
2. 四类网络均可使用 Mock 展示和切换。
3. 图谱支持缩放、平移、节点拖动、节点选择和边选择。
4. 搜索可以定位并高亮节点。
5. 节点和关系详情与选中对象一致。
6. 概念论文可以按 JIF 或年份排序。
7. 作者合作边宽能反映共同论文数。
8. 加载、空数据、错误和重试状态完整。
9. 小屏幕仍可使用图谱和详情区。
10. 测试、代码检查和正式构建通过。

## 15. 首版明确不包含

- 新增、修改或删除图谱节点与关系；
- 在图谱页显示或处理待审核建议；
- 保存节点拖动后的坐标；
- 导出图片或数据文件；
- 复杂筛选、多选、框选和批量操作；
- 一次加载完整领域图谱；
- 真实后端接口；
- 期刊节点；
- 方法共同使用等未进入当前契约的派生关系；
- 完整键盘图遍历。

## 16. 后续演进

A 确认接口后，`graph.service` 从 Mock 切换到正式 Graph、ConceptPaper 和 Author API。若图谱规模增大，再增加按中心节点加载局部图、深度限制、类型筛选和服务端节点上限；这些能力不提前进入首版。
